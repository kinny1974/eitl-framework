**Optimizaciones aplicadas en 1.0b**: (1) la persistencia O(n²) quedó **resuelta** con la

con un trade-off medido de ~15–30% menos ops/s en bench secuencial (overhead de promesa),
aceptable si prima la concurrencia real; decisión documentada en D-009; (3) la salida es
**determinista** (`Intl.NumberFormat("en-US")` fijo, M7/B3 resuelto).

## 7.5 Re-ejecutar la auditoría (comandos)

### a) Requisitos

- **Node.js ≥ 22.6** y **npm** en el PATH.

### b) Tests, cobertura, type-check y benchmarks (Gate 4/5/6)

```bash
# Desde la raíz del bundle
cd framework/.opencode/plugin

# 1. Instalar dependencias (solo la primera vez)
npm install

# 2. Type-check — debe terminar con exit 0 (Gate 5)
npm run typecheck

# 3. Pruebas unitarias + cobertura — 45/45 y cobertura 100% (Gate 4)
npm run test:coverage

# 4. Benchmarks de rendimiento — NFRs con margen ≥ 10% (Gate 6)
npm run bench
```

> 💡 `npm test` ejecuta la suite completa (incluye el test de estrés/memoria de 2,000
> checks). Ejecutar todos los comandos puede tardar 1–2 minutos según la carga.

### c) Verificación estructural del bundle

```bash
# 10 agentes y 21 skills
ls framework/.opencode/agents/ | wc -l      # → 10
ls framework/.opencode/skills/ | wc -l      # → 21

# Sintaxis de los scripts de inicialización
bash -n init-scripts/init-eitl.sh && echo "SH OK"

# Windows: parse del script PowerShell (PowerShell 7+)
pwsh -NoProfile -NonInteractive -Command '$e=@();$t=@();[void][System.Management.Automation.Language.Parser]::ParseFile("init-scripts/init-eitl.ps1",[ref]$t,[ref]$e);if($e.Count){$e|ForEach-Object{"PARSE ERROR: "+$_.Message};exit 1}else{"PS1 OK"}'
```

### d) CI automatizada (T-12, en 1.0b)

El bundle incluye un workflow de GitHub Actions (`.github/workflows/ci.yml`) con 4 jobs
que se ejecutan en cada push a `main` y en cada PR:

| Job | Valida | Equivalente |
|-----|--------|-------------|
| `plugin` | `npm run typecheck` + `test:coverage` (thresholds ≥ 80%) + `bench` | Gates 5, 4 y 6 |
| `bundle` | 10 agentes / 21 skills, `bash -n` del `.sh`, JSON/JSONC válidos, sin secretos (H1/T-10), reemplazo de `.opencode` (M8/T-21), `MEMORY_ENABLED` (M5/T-17), nomenclatura unificada (M3/T-15), validator 6 gates (M9/T-16) y plugins npm verificados (L1/T-18) | Estructura del bundle + anti-regresiones |
| `e2e` | `e2e/smoke-e2e.sh` — inicialización, estructura y re-inicialización sin anidamiento | E2E estructural (T-13) |
| `powershell` | Parse de `init-eitl.ps1` (windows-latest) | Sintaxis PowerShell |

> 💡 El smoke live de OpenCode (`OPENCODE_SMOKE=1`, requiere CLI `opencode` + LLM real)
> se ejecuta bajo demanda fuera de la CI por defecto — ver `e2e/smoke-e2e.sh` §6.

Para que la CI funcione, `package.json`/`package-lock.json` del plugin se versionan
(ya no están en el `.gitignore`). Los **thresholds de cobertura ≥ 80%** en
`vitest.config.ts` hacen fallar la CI si la cobertura baja del Gate 4.

### e) Actualizar la línea base tras re-ejecutar

1. Lee los nuevos números de la salida de `npm run test:coverage` y `npm run bench`
   (o del job `plugin` de la CI).
2. Actualiza las tablas de [`eitl-artifacts/04_Test_Report.md`](../eitl-artifacts/04_Test_Report.md),
   [`05_QA_Report.md`](../eitl-artifacts/05_QA_Report.md) y
   [`06_Performance_Report.md`](../eitl-artifacts/06_Performance_Report.md).
3. Marca en [`eitl-artifacts/TASKS.md`](../eitl-artifacts/TASKS.md) las tareas resueltas
   y añade nuevas entradas a [`eitl-artifacts/DECISIONS.md`](../eitl-artifacts/DECISIONS.md).
4. Refleja el estado en [`eitl-artifacts/CURRENT_STATE.md`](../eitl-artifacts/CURRENT_STATE.md).
